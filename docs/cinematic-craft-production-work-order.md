# 시네마틱 레퍼런스 영상 분석·재현 설계 작업지시서

- 문서 상태: 구현 작업 기준안
- 목적: 레퍼런스 영상 하나를 입력하면 제작자가 결과물을 재현할 수 있도록 영상의 관찰 사실, 제작 기법, 추론, 작업 절차, 도구·모델 후보와 근거를 구조화하여 산출한다.
- 적용 범위: Flucto의 기존 로컬 영상 분석·CSV 기능을 운영 가능한 제품으로 완성. 이 문서의 “모방”은 기법과 제작 구조의 학습·재현을 뜻하며, 저작권 침해·출처 은폐·특정 창작자의 식별 가능한 스타일 복제를 목표로 하지 않는다.

## 1. 완료 정의

사용자가 로컬 영상 파일 또는 지원되는 URL을 제공하고 권리·전송 고지를 확인하면 시스템은 다음을 제공해야 한다.

1. 입력 출처·메타데이터·분석 범위·누락 및 신뢰도를 기록한다.
2. 샷 경계와 씬 묶음을 분리해 타임코드 기준으로 검토 가능한 샷 로그를 만든다.
3. 프레임에서 직접 보이는 내용, 오디오/자막에서 확인된 내용, 모델의 추정, 확인 불가 사항을 구분한다.
4. 각 샷의 시각·청각 기법, 편집 전환, 서사 기능 추정, 제작상 선택을 증거와 함께 정리한다.
5. 분석된 결과에서 재현 가능한 제작 계획을 생성한다. 단계, 작업, 입력, 도구, 모델 후보, 설정·프롬프트 초안, 예상 산출물, 검수 기준, 대체안을 포함한다.
6. 영상 모델·편집·합성·색보정·오디오 도구 추천은 검증 가능한 기능·버전·접근일·출처와 연결한다. 근거가 없으면 추천 불가/미확인으로 표시한다.
7. Excel 호환 CSV 세트와 기계 판독용 JSON을 내보내고, 사용자는 앱에서 결과를 검토·수정·재실행할 수 있다.
8. 실패·부분 분석·표본화·비용·외부 전송을 정직하게 표시하고, 결과물을 재현 가능한 운영 로그와 함께 관리한다.

“그대로 재현”은 시스템이 실제 원본 촬영 현장, 사용한 카메라, 렌즈, 조명, 소프트웨어, 모델을 영상만으로 확정할 수 있다는 뜻이 아니다. 관찰 사실과 제작 의도/도구의 추정을 절대 혼동하지 않는다. 실물 도구는 원본 제작 크레딧·프로젝트 파일 등 출처가 있는 경우에만 확인됨으로 분류한다.

## 2. 현 상태 및 미완료 범위

현재 코드에는 로컬 파일 입력용 CLI 분석, ffmpeg 컷 후보·일부 신호, 선택적 Vision 라벨링, taxonomy 입력, 두 CSV 출력이 있다. 이를 제품 완성으로 간주하지 않는다.

미완료/위험 항목:

- URL·검색 결과에서 분석까지 이어지는 다운로드/권리/재시도 흐름이 없다.
- 데스크톱 화면, IPC, 사용자 검토·수정·작업 재개 기능이 없다.
- 씬은 컷 번호 기반 묶음에 가깝고 서사적 씬 분류가 없다.
- 컷은 장면 변화 점수에 기반하며 양쪽 프레임 확인과 전환 유형 검증이 부족하다.
- 움직임 지표는 실제 카메라/피사체 움직임을 분리하지 못하며 오디오 RMS는 비어 있다.
- 책 지식은 내장 추출 파이프가 아니라 제공된 JSON에 의존한다. 기존 taxonomy가 실제로 생성·검토되었다는 증거가 없다.
- 매칭은 간단한 anchor/신호 규칙이다. 장면 전체의 기법·인과·제작 선택을 충분히 구조화하지 않는다.
- 도구/영상 모델 추천 카탈로그와 버전·기능·출처·적합성 검증이 없다.
- 실제 영상 end-to-end 품질, 대용량·고장·성능·보안·비용 운영 검증이 없다. 관련 테스트 중 경로 테스트 실패가 보고되어 플랫폼별 정리가 필요하다.
- `OBSERVED/ESTIMATED/UNKNOWN` 수준이 전 단계의 필수 데이터 계약으로 강제되지 않았다.

## 3. 핵심 원칙과 데이터 신뢰 등급

### 3.1 증거 등급

각 필드 및 주장에 아래 값과 근거 참조를 기록한다.

- `OBSERVED`: 프레임/오디오/자막/메타데이터에서 직접 검증. evidence span(시간 범위·프레임 샘플·텍스트)을 필수로 연결한다.
- `SOURCE_CONFIRMED`: 크레딧, 원본 설명, 제작자 제공 자료 등 독립 출처가 명시적으로 확인. 출처 URL/문서·접근 시각 필수.
- `INFERRED`: 영상 증거로 가능한 설명이나 유일한 해석은 아님. 추론 사유·신뢰도·대안 설명을 기록한다.
- `UNKNOWN`: 정보가 부족하거나 도구가 판별할 수 없음. 추측으로 채우지 않는다.

LLM 결과는 `OBSERVED`나 `SOURCE_CONFIRMED`가 될 수 없다. 독립 검증자/규칙 검증 전에는 `INFERRED`다. 수동 검토는 검토자·시각·필드별 변경 이력으로 기록한다.

### 3.2 재현 가능성과 정직성

- 각 관측·추론·추천은 샷 ID와 시간 범위, 모델/규칙 버전, 입력 해시, 생성 시각을 보유한다.
- 전 영상 분석인지 표본인지, 빠진 구간·손상 구간·API 미실행 여부를 결과 첫 화면과 데이터에 표기한다.
- 카메라/렌즈/장비/실제 편집 프로그램은 영상만 보고 확정하지 않는다. 시각적 효과로 추정되는 경우에도 대안 도구와 한계를 명시한다.
- 서비스/API/모델 카탈로그는 운영자가 업데이트·폐기·버전 고정할 수 있어야 한다. 최신성 검증 없이 특정 모델을 단정 추천하지 않는다.

## 4. 목표 산출물과 스키마

기본 산출은 JSON 정규 데이터와 그로부터 결정론적으로 생성하는 CSV다. CSV만을 원본 데이터 저장소로 삼지 않는다. 기존의 프레임 디스크 미저장 정책을 기본값으로 유지하고, 증거 프레임 전송·저장은 별도 동의 및 보존기간 정책 없이 허용하지 않는다.

### 4.1 필수 파일

- `analysis.json`: 전체 정규 결과, 버전 포함.
- `shots.csv`: 1행/샷. 샷 ID, 씬 ID, in/out, 지속시간, 경계 유형·확신도, 관찰된 피사체/행동/구도/샷 크기/카메라 움직임/조명/색/초점/심도 추정, 편집·전환, 오디오 이벤트, 서사 기능 추정, 각 주장별 evidence ID·신뢰도·상태.
- `scenes.csv`: 1행/씬. 씬 시작·종료, 장소/시간대 추정, 인물·목표·행동·극적 변화, 샷 구성·리듬·근거, 불확실성.
- `techniques.csv`: 1행/기법 적용 사례. 기법 ID, 정의, 영상 내 적용 샷/시간, 관찰 근거, 기법이 만든 효과의 추정, 재현 지시, 대안 및 실패 방지.
- `production_plan.csv`: 1행/작업. 제작 단계, 작업 선행조건, 입력, 구체 작업, 설정/파라미터, 프롬프트 초안, 산출물, 완료·검수 조건, 소요/비용 범위(근거 있을 때만), 위험·대안.
- `tool_recommendations.csv`: 1행/도구 추천. 작업 목적, 프로그램/서비스/모델, 적합한 기능, 입력/출력 제약, 추천 근거/evidence ID, 출처·버전·확인일, 가격/라이선스 근거 또는 UNKNOWN, 적합도·대안.
- `evidence.csv`: 1행/근거 span. evidence ID, 유형(프레임/오디오/자막/크레딧/외부 출처), 시간 구간 또는 URL, 요약, 증거 수준, 추출기/모델 버전, 데이터 전송 여부.
- `manifest.json`: 입력 식별·해시(민감정보 최소화), 도구 및 모델 버전, 구성, 시작/종료/상태, 입력·출력 파일, 누락·오류·표본화·비용 집계.

모든 CSV는 RFC 4180, UTF-8 BOM, CRLF, 안정적인 컬럼 순서/enum, null과 빈 문자열의 의미를 명세한다. 스키마에 `schema_version`을 둔다. 긴 JSON 배열은 CSV 내부 임의 구분자에 의존하지 말고 JSON 파일의 정규 배열을 참조하거나 표준 JSON 문자열로 인코딩한다.

### 4.2 최소 JSON 개념 모델

`AnalysisRun`은 `source`, `coverage`, `evidence[]`, `scenes[]`, `shots[]`, `techniqueApplications[]`, `productionPlan[]`, `toolRecommendations[]`, `limitations[]`, `provenance`, `manifest`를 포함한다. 모든 엔티티는 안정 ID를 가지며, 참조 ID는 검증 단계에서 dangling reference가 없어야 한다.

`Shot`은 시간범위·경계 근거·`observations[]`·`interpretations[]`·`audio[]`·`text[]`·`techniqueApplicationIds[]`를 가진다. 값 하나의 신뢰도를 샷 전체에 뭉뚱그리지 않는다.

## 5. 작업 단계 및 수용 기준

### M0 — 요구사항·검증 데이터·계약 확정

작업:

1. 이 문서를 기준으로 JSON Schema, CSV 컬럼/enum 사전, evidence/provenance 정책, 상태 머신을 작성한다.
2. 대표 레퍼런스 20개 이상을 권리 상태 확인 후 선정한다. 광고/대화/뮤직비디오/튜토리얼/세로 숏폼/애니메이션/저조도/빠른 컷/페이드 포함.
3. 각 영상에 경계·씬·샷·오디오/텍스트·기법을 사람이 이중 주석하고 불일치는 조정한다. 얼굴/인물 민감 데이터의 보관·접근 정책을 정의한다.
4. 제품 요구를 URL 직입력, 로컬 파일, 대형 파일, API 미설정, 오프라인, 사용자 검토 가능성으로 구분한다.

완료 기준: 버전된 스키마와 주석 가이드, 골드 데이터, 권리/프라이버시 정책이 리뷰 승인됨. “전부 분석”의 실측 커버리지 목표를 영상 유형별로 합의함.

### M1 — 안정적인 ingest·작업 관리

작업:

1. 로컬 파일과 지원 URL 입력을 공통 `SourceResolver`로 정규화한다. URL은 허용 플랫폼·다운로드 가능 여부·지역/로그인 제한을 명시하고, 허용되지 않은 URL은 안전하게 거부한다.
2. 기존 downloader/yt-dlp 경로를 재사용하되 다운로드 후 분석은 로컬 파일을 기준으로 한다. URL 메타데이터·리다이렉트·파일 형식 검증, 중단/재개, 임시파일 정리, 디스크 여유 공간 확인을 구현한다.
3. 작업 상태(`queued/probing/detecting/labeling/reviewing/exporting/completed/partial/failed/cancelled`)와 재시도·취소·재개·진행 이벤트를 구현한다. 중복 실행·출력 경로 충돌을 막는다.
4. ffmpeg/ffprobe 기능·버전 검증, 하위 프로세스 타임아웃·취소·stdout/stderr 상한·리소스 제한을 둔다.
5. 로컬 분석 기본. 외부 Vision/ASR 전송 전 별도 명시 동의, 전송할 데이터·공급자·비용 예상·보존 고지를 보여준다.

완료 기준: 정상 URL/로컬/잘못된 입력/네트워크 단절/디스크 부족/취소 후 재개가 테스트되고 원치 않는 파일·프레임이 남지 않는다.

### M2 — 샷 경계·신호 추출 정확도

작업:

1. scene score 후보만으로 확정 컷을 만들지 않는다. 경계 전후 프레임 차이, 지속시간, 페이드/디졸브/와이프/플래시 구분을 검증하며 각 경계에 근거와 confidence를 둔다.
2. VFR·타임베이스·회전·잘못된 duration·가변 프레임레이트를 고려해 타임코드가 원본 기준으로 안정적이어야 한다. 경계 tolerance는 골드셋에서 정한다.
3. `motion`을 밝기 분산으로 대체하지 않는다. 광학 흐름 또는 검증된 모션 신호를 적용하고 카메라 이동/피사체 이동은 영상만으로 구분 불가할 수 있음을 표현한다.
4. 오디오 RMS, loudness, silence, onset/음악 변화 등 지표를 실제 계산하고, 편집 컷과 오디오 이벤트를 별도 트랙으로 정렬한다. 음성 전사는 별도 기능·동의·언어 지원 정책으로 설계한다.
5. 분석 비용을 제한하기 위해 저해상도 전수 pass + 후보 구간 정밀 pass, 샘플링 상한, 길이·컷 상한을 구현한다. 표본 실행 시 범위와 누락률을 기록한다.

완료 기준: 골드셋 컷 검출 precision/recall 및 경계 오차를 유형별 공개. 프로젝트 합의 목표(권장 초기값: 일반 컷 F1 ≥0.90, 중앙 절대 오차 ≤2프레임)를 통과하고 특수 전환 성능은 별도 표기. 못 맞춘 유형은 `UNKNOWN/ESTIMATED`로 강등.

### M3 — 씬·샷·시청각 의미 분석

작업:

1. 샷 분할과 씬 분할을 분리한다. 씬은 시각적 연속성, 인물/장소, 시간, 행동 맥락을 결합하고 자동 묶음 근거와 대체 경계를 보존한다.
2. 프레임 대표 샘플 선택은 시작/중간/끝 고정만이 아니라 변화점과 다양성을 반영한다. 프레임은 메모리 처리, 해상도 제한, 샷별/API별 예산 상한을 적용한다.
3. 라벨을 세부 필드별로 생성한다: shot scale, angle, composition, subject/action, camera/subject motion, focus/depth, lighting, palette, transition, pacing. 화면에 없는 장비·렌즈는 추론 또는 UNKNOWN이다.
4. 자막/음성/음악 분석은 별도 capability로 설정하고 언어·정확도·동의·전송 여부를 기록한다. 자막은 사실성 검증 전 직접 인용·전사본 출력 정책을 따른다.
5. 비전 모델 출력은 JSON Schema로 검증하고 prompt/model/version, confidence, 실패, retry를 기록한다. 모델이 근거 시간 범위를 제공하지 못하면 근거를 생성하지 않는다.
6. 씬 요약은 샷별 근거에 연결한다. 이야기 기능·감정 효과는 추론이며 대안 설명을 제공한다.

완료 기준: 골드셋에서 필드별 정확도·coverage·신뢰도 calibration 보고서가 있다. 기준 미달 필드는 UI/CSV에 추론/미확인으로 표시한다. Vision 미설정에서도 신호 CSV와 상태가 정상 출력된다.

### M4 — 기법 지식베이스 및 적용 설명

작업:

1. 기존 `craftTaxonomy` heading 추출은 초기 seed 생성기로만 취급한다. 책·스킬 등 출처별 권리와 인용 제한을 검토하고 원문 장기 저장을 금지한다.
2. 각 기법 항목에 정규화 ID, 정의(패러프레이즈), 목적/효과, 적용 조건, 실행 절차, 필요한 리소스, 실패 패턴, 대안, 관찰 가능한 단서, 출처 locator, 검토 상태·버전을 둔다.
3. taxonomy 항목을 영상 적용과 구분한다. 카탈로그의 존재만으로 영상에서 사용했다고 매칭하지 않는다. 기법 적용은 샷/씬 evidence와 추론 설명이 있어야 한다.
4. 중복·동의어·KO/EN 용어를 정규화하고 도메인 전문가 검토 흐름을 둔다. 미검토 기법은 추천 근거로 제한한다.
5. 검색·매칭은 규칙/임베딩/LLM 후보를 결합하되, 최종 링크는 근거 기반으로 저장한다. 매칭 불가 항목을 억지로 taxonomy에 붙이지 않는다.

완료 기준: seed와 검토된 taxonomy를 분리하고 모든 기법 적용 행이 evidence 및 taxonomy version을 가리킨다. 출처·저작권 감사 통과.

### M5 — 재현 가능한 제작 계획·프로그램/모델 추천

작업:

1. 분석 결과를 제작 단계(기획/프리프로덕션/촬영 또는 생성/편집/사운드/색보정/납품)로 변환하는 planner를 구현한다. 단계별 작업은 관찰·추론에서 역추적 가능해야 한다.
2. 각 작업에 구체 입력, 준비물, 촬영/생성 지시, 샷 리스트, 구도·움직임·조명·리듬 목표, 실행 순서, 산출물, 품질검사 및 대안 경로를 포함한다.
3. 도구 추천은 능력 기반 카탈로그로 구현한다. 편집기, 합성기, 오디오, 색보정, 실제 촬영 장비, 영상 생성 모델은 서로 다른 범주다. 지원 입력/출력, aspect/duration, 제어 기능, 라이선스/지역/접근성, 버전·확인 날짜·출처를 관리한다.
4. 특정 도구/모델의 기능 및 가격을 근거 출처 없이 생성하지 않는다. 추천 rationale이 evidence 및 capability catalog에 연결되지 않으면 `UNKNOWN`으로 둔다. 동등한 대안과 수동 워크플로우를 제공한다.
5. 생성 모델이 특정 샷을 정확히 만들 수 있다고 보장하지 않는다. 재현 난이도·모델 변동성·반복 생성 및 후반 보정 필요성을 명시한다. 프롬프트는 저작권/스타일 모방 제한을 포함하고 장면의 일반적 기술 요소로 서술한다.
6. production plan은 사용자가 목표(예산, 장비, 숙련도, 로컬/클라우드, 라이선스 제약)를 입력하면 그에 맞게 대안·범위·비용을 제시한다. 가격 미확인 시 금액을 산출하지 않는다.

완료 기준: 사람이 계획만으로 샷별 실행과 납품 검수를 진행할 수 있는지 크리에이터 사용자 테스트를 수행한다. 각 지시의 증거/추론/도구 추천 근거와 버전을 추적할 수 있다.

### M6 — 데스크톱 UX·리뷰·내보내기

작업:

1. 앱에서 URL/파일/히스토리 선택, 권리·전송 고지, 분석 범위/예산 설정을 제공한다.
2. 진행 단계·예상 시간/비용·중단/재개·부분 실패를 제공한다. 민감한 key는 UI/로그에 노출하지 않는다.
3. 씬 타임라인과 샷 표를 동기화하고 증거를 확인할 수 있게 한다. 사용자는 경계·라벨·추론을 편집하고 변경 이유를 남긴다. 원본 프레임은 기본 저장하지 않는다.
4. 재현 계획과 도구 추천을 근거 링크와 함께 보여준다. 근거 없는 단정 추천을 차단한다.
5. 전체 CSV/JSON 또는 선택 범위 내보내기, 안정적 파일명, 재내보내기, 스키마 버전을 지원한다.
6. 분석 세션 이력, 삭제/보존 정책, 재현 가능한 실행 설정, 실패 로그(개인정보 제거)를 관리한다.

완료 기준: 키보드 접근성·긴 영상 UX·오류 회복·CSV Excel 호환성 사용성 테스트를 통과한다. IPC sender 검증과 권한 경계가 있다.

### M7 — 운영·보안·품질 게이트

작업:

1. 전체 단위/통합/E2E 테스트: 실제 fixture 영상(권리 정리), ffmpeg mock, 네트워크 장애, Vision provider 응답 오류, 출력 검증, Windows/macOS/Linux.
2. 회귀 벤치마크: 컷/씬/필드별 precision·recall·coverage·calibration·사용자 수정률을 버전 간 비교한다. 골드셋 변동은 리뷰 승인을 요구한다.
3. 성능/비용: 길이·해상도별 실행시간, 최대 RAM, 임시 디스크, 외부 호출 수/bytes를 측정. 동시성·취소·요금 상한을 강제한다.
4. 보안: URL SSRF 및 로컬 경로 권한, 명령 인자 주입, 다운로드 경로 traversal, 악성 미디어, 파일 크기/압축 폭탄, API key, 모델 프롬프트 인젝션을 점검한다. 임의 원격 URL fetch는 allowlist/네트워크 정책을 적용한다.
5. 개인정보: 전송 전 동의, 최소 프레임/해상도, 로그 비식별화, 파일 삭제, 보존기간, 외부 공급자 약관·학습 사용을 명시한다.
6. 관측성: 오류 유형·단계·버전·성능·coverage를 개인정보 없는 이벤트로 수집(사용자 동의/정책 적용). 공급자 장애·모델 변경·카탈로그 만료 알림과 롤백 절차를 마련한다.
7. 운영 문서: 사용자 가이드, 지원 입력/제약, known limitations, 비용/전송 표, 문제해결, 버전 호환성, 장애 대응/runbook을 작성한다.

완료 기준: release checklist, 플랫폼 CI, 보안 리뷰, 데이터 삭제 검증, 지원·장애 대응 담당/경로가 승인됨. 릴리스 전 공개 known-limitations와 quality report를 생성한다.

## 6. CLI/IPC/API 구현 계약

- `flucto analyze <path|url|--history N> --craft DIR --profile ...`는 공통 서비스 계층을 호출한다. URL은 명시적 다운로드 동의가 필요하다.
- `--dry-run`은 분할 후보 수, 표본화 예상, API call/frame 수, 가능한 비용 범위를 표시한다. 비용을 모르는 provider는 UNKNOWN.
- `--allow-vision-api` 외부 전송 동의는 실제 전송 데이터와 공급자를 제시한 동의 기록이어야 하며, 플래그만으로 포괄적 동의로 해석하지 않는다.
- `--json` 결과에는 성공/부분/실패, 단계별 상태, 모든 산출물, 누락, 비용/호출, `rows_incomplete`, schema version을 포함한다.
- 취소는 하위 프로세스와 네트워크 요청에 전파되고 임시 리소스를 정리한다. 재개는 안전한 체크포인트만 사용하고 중복 출력 방지.
- Electron IPC 채널은 sender 권한·payload schema·파일 경로 검증을 거치며 renderer에 임의 파일 접근을 노출하지 않는다.

## 8. 구현 진행 현황

### 현재 작업 세션에서 구현한 기반

- `schemas/analysis-run.v1.schema.json`: 근거 연결형 JSON 계약 초안. `analysis.json` 산출, 런타임 JSON Schema 검증(Ajv), ID/증거 교차 참조 검증이 구현되었고 CSV 세트는 해당 JSON과 같은 분석 결과에서 생성된다. 권리 확인 gold-set 기반 정확도 평가는 아직 없다.
- OpenCode 바이너리 빌드 준비: 공식 릴리스의 OS/아키텍처별 바이너리를 pinned version + pinned SHA-256으로 검증해 앱 `bin` 리소스에 포함. 현재 pin은 `1.19.3`; macOS universal에는 두 아키텍처 바이너리를 각각 포함한다.
- `OpenCodeRuntime`: loopback-only 인증 서버, 격리 설정·홈·데이터·상태·캐시 경로, provider API key의 런타임 전달, 종료 시 임시 데이터 정리.
- 모델 목록은 OpenCode `/provider` 카탈로그에서 이미지 입력, 양쪽 가격 0, 이름/ID의 명시적 free 표기를 모두 확인한 항목만 선택지로 제공한다. 카탈로그 가격은 무료 사용·접근·쿼터를 보장하지 않으며 공급자별 실제 조건을 확인해야 한다.
- AI 설정 UI: provider/model 선택, 강도, API key 입력/교체/삭제. 키는 OS keychain-backed Electron safeStorage 사용 가능 시에만 저장하고 plaintext fallback은 금지한다.
- Desktop 로컬 파일 또는 HTTPS 지원 플랫폼 URL 분석 경로와 매 실행별 외부 프레임 전송 동의를 추가했다. URL은 권한 확인 후 다운로드하며 원본은 결과 폴더 `source/`에 남는다.
- 프레임 추출을 샷 초반 연속 프레임에서 샷 구간에 분산된 대표 샘플로 변경하고 JPEG stdout pipe 크기 상한을 적용했다. luma 신호는 2 Hz, RMS는 48k-sample windows로 제한해 고해상도·장시간 입력 메모리 폭증 위험을 낮췄다.
- Windows 경로를 Linux 테스트에서 처리하지 못하던 ffprobe 경로 조합 버그 수정.

### 아직 남은 필수 작업

이 기반은 운영 가능한 완료 상태가 아니다. 샘플 MP4의 실제 ffmpeg 분석·전체 CSV/JSON 산출 및 schema validation은 실행했지만, OpenCode 실제 provider 프레임/API 호출 E2E, 전체 지원 플랫폼의 설치·업데이트 검증, 권리 승인 gold-set 및 정확도 평가, 경계/씬 분할 정확도, 광학 흐름·의미 오디오, taxonomy 검토, 영상 생성 모델 후보 검증, 비용/접근성·예산 설정, 취소/재개, 편집 가능한 사용자 리뷰 UI, SSRF/악성 미디어 방어 및 보안·운영 게이트는 미완료다. 현재 도구 추천은 제한적이다. 공식 기능 출처를 연결한 DaVinci Resolve 편집기 추천과 명시적 CGI/애니메이션 추정 시 Blender 후보만 생성하며, 가격/라이선스는 unknown이다. 영상 생성 모델 capability가 실제 검증되지 않았으므로 생성 모델을 추천하지 않는다. 아래 릴리스 체크리스트는 미완료 상태로 유지한다.
